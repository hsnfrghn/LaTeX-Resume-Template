% Bullet list spacing
%--------------------
% Hsn added: PLAN.md R1 cut lever 2, applied after the build hit the 2-page fatal error.
% Hsn added: itemlist is defined in Code/CV.cls with \itemsep 5pt; redefined here rather
% Hsn added: than edited there, for the same reason the column widths are (D2) -- the
% Hsn added: upstream class stays byte-identical and every local change is in one place.
% Hsn added: Three savings, all free of content loss:
% Hsn added: (1) \itemsep 5pt -> 2pt. This is the gap *between* items, so with 10 bullets
% Hsn added:     in five lists there are five such gaps: 15pt, about a line and a half.
% Hsn added: (2) \topsep and \partopsep to 0pt. These are the bigger win -- itemize adds
% Hsn added:     them above and below every list, so five lists pay it ten times over.
% Hsn added:     Both must be set before \begin{itemize}, not after: \list reads them when
% Hsn added:     the list opens, so setting them inside (as the class does for \itemsep,
% Hsn added:     \parskip and \parsep, which are per-item and therefore fine there) would
% Hsn added:     be too late to have any effect.
% Hsn added: (3) \leftmargini 2.5em -> 1.2em. itemize indents every bullet by ~2em, which
% Hsn added:     is width taken straight out of a 10.9cm column and paid back in wrapped
% Hsn added:     lines. It must be set outside the environment, since \list reads it when
% Hsn added:     the list begins.
\renewenvironment{itemlist}{%
        \setlength{\leftmargini}{1.2em}%
        \setlength{\topsep}{0pt}%
        \setlength{\partopsep}{0pt}%
        \begin{itemize}
        \setlength{\itemsep}{2pt}
        \setlength{\parskip}{0pt}
        \setlength{\parsep}{0pt}
    }{%
        \end{itemize}%
    }%

%--------------------
% Hsn added: \dotline is defined in Code/CV.cls ending in \medskip (~6pt). It is used in
% Hsn added: exactly one place, the page-1 sidebar, six times -- 36pt of pure white space
% Hsn added: in the column that decides whether page 1 fits at all. Dropping to \smallskip
% Hsn added: recovers about 18pt, which is nearly two lines, and costs no content and
% Hsn added: almost no legibility: the dashed rule itself already separates the blocks.
% Hsn added: Redefined here, not in the class, per D2.
% Hsn added: Why this lever and not another: measured with the page limit lifted, the
% Hsn added: sidebar is the taller column and the two-column row is one unbreakable
% Hsn added: minipage box, so the block needed to lose ~5pt to fit the 624pt left on
% Hsn added: page 1 after the header and summary. Spacing was the only thing left that
% Hsn added: was not a fact.
\renewcommand{\dotline}{\noindent\textcolor{soft_text}{\hdashrule{\linewidth}{0.6pt}{0.5ex}}\smallskip}

% Experience entry macro
%--------------------
% Hsn added: single entry macro for Experience. Every position now carries a start
% Hsn added: date, end date and employment type; centralising the layout here keeps
% Hsn added: the five entries identical by construction and makes a future restyle a
% Hsn added: one-line change. Line 1 is title (bold, left) + dates (accent, right) so
% Hsn added: the two scan columns a recruiter reads align; line 2 carries company,
% Hsn added: city and employment type, which is worth the space because not all five
% Hsn added: positions are full-time.
% Hsn added: \hspace{\stretch{1}} rather than \hfill: inside CVbody \raggedright sets
% Hsn added: \rightskip to 0pt plus 1fil, which would split the slack with an \hfill
% Hsn added: and leave the dates floating mid-line. \stretch{1} is fill-order, so it
% Hsn added: wins and the dates sit flush against the right edge of the column.
% #1 title  #2 company  #3 city  #4 employment type  #5 dates
\newcommand{\CVjob}[5]{%
  \textbf{#1}\hspace{\stretch{1}}{\small\textcolor{icons}{\textit{#5}}}\\[0.1em]
  {\small\softtext{\textit{#2, #3}}~\softtext{\textbullet}~\textcolor{icons}{#4}}\par
  \vspace{0.15em}%
}
